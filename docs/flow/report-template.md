# 进化报告模板

适用：进化流程第五步。每次进化结束按本模板向用户输出，共三节，不增删章节。

只写结论，不复述工具输出。异常必须附原文片段。

```markdown
## 🧬 进化报告 <YYYY-MM-DD HH:MM>

**1️⃣ 结果**

候选审查：共 X 个。候选区为空时写「0 候选」。

| 候选 | 结论 | 原因 |
|---|---|---|
| <slug> | 启用 / 淘汰 / 并入 | 一句话原因 |

技能变更：
- 新启用：<name>，来源会话，软链或加载验证通过或失败
- 更新：<name>，改了什么与为什么
- 归档或淘汰：<name>，依据为使用次数、最后使用时间、失败原因，附用户决策
- 问题与闲置技能须附使用次数与成功/失败/未知计数，让用户一眼看清每个技能的实际表现

记忆与文档：
- USER.md：新增 N 条，主题一句话概括，当前总条数与文件字节数
- LESSONS.md：新增 N 条，各一句话主题
- 画像草稿：N 份，提炼 M 条，归档位置
- 其他文档同步项

**2️⃣ 关键命令与系统状态**

| 命令 | 结果 |
|---|---|
| evolve_brief.sh | 关键事实，如启用区计数与超长技能 |
| healthcheck.sh | 执行了哪几项，全部通过或异常原文 |
| git commit | hash 与 message 首行 |

- state.json 计数变化：`skillsEnabled`、`skillsUpdated`、`skillsRepaired` 等，写作「前 → 后」
- 记分卡摘要：优秀、健康、未观测、问题、闲置、元技能各几个
- 技能总量：当前 X/40
- 本轮 LLM 调用次数与成本

**3️⃣ 待用户决策**

逐项列出，每项写明建议动作与依据。无则写「无」。
```

## 报告纪律

- 报告是给用户的决策材料，不是执行日志。工具输出、文件内容、命令回显都不进报告。
- 计数必须来自实测或脚本输出，不凭印象填写。
- 待用户决策一节不得省略。拿不准的判断、涉及删除或压缩的动作、仅有单次证据的画像信息都在这里提出。
